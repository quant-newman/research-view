## 本批做了什么

1. **hotspots / research_digest 输入指纹门控**(sql/032 两列 nullable,不回填):同指纹复用
   已落库叙述,不调 LLM;统计行仍每档重算。
2. **美股 B1 译文缓存**:`exports/us_b1_cache.json`,key=sha1(命名空间|标题|摘要),7 天 TTL,
   原子替换,失败批不入缓存;`_b1_batch`/`_b1_wire` 只把 miss 送 LLM。
3. **失败不落指纹**:两处 LLM 降级兜底时 sig 置空,下一档必须重试,兜底文案不会被钉一整天。

## 关键设计取舍

- 热点指纹**排除 ret_1d 与主力净额尾数**。这两个是连续行情量,每档都在动;放进指纹会让它
  恒变、门控形同虚设(等于白改)。它们的最新值本来就由统计行每档重算后直接展示,叙述层
  不刷新不影响看板数字。方向性大位移仍会触发重算(净额按 5 亿粗档进指纹)。
- 译文缓存无口径风险:temperature=0 的"只翻译不判断",输出是标题的确定性函数。
- **判断链零触碰**:B1–B8 的 prompt / 口径 / 权重 / 发卡 / 记分全不动。复用的只是"同一输入下
  本来也会重新生成的同一份叙述"。#41 硬闸不适用(展示层降本,先例 #44 / #45)。

## 评估但未采纳(留档防重议)

- A股 B1 逐条 → 批量(10–15条/批):省得最多,但有批内串扰/序号错位风险,单独排期。
- 机械活降级 v4-flash 小模型:省钱幅度最大,但有可感知的质量损失,待使用者拍板。
- 盘中 hotspots 降频到每小时:与指纹门控重叠,门控更精准(该变时立刻变)。
